# Architecture rules
- Keep customer price proposals separate from catalog prices: server-validate published products, save private submissions, expose admin-only reads through RLS and send fixed-recipient event-deduplicated notifications; proposals must never change checkout prices.
- Keep hero chocolate lettering as localized Unicode text with a shared chocolate texture and explicit translations for every supported language, preserving native script shaping without per-language image generation; retain the original Latvian artwork.
- Keep product visualization generation in its dedicated Edge Function, with durable request IDs, bounded generation, private storage, session-scoped visitor history, protected admin reads and fixed-recipient event-deduplicated emails; never expose client designs publicly.
- Normalize visualization logo uploads to bounded PNGs in the browser, sanitizing SVG and rendering only the first PDF/TIFF page; keep server image validation strict so active document formats never reach private image storage or the image model.
- Accept design reference selections cumulatively without a file-count cap, process sequentially and combine them into a bounded private contact sheet; this preserves provider payload limits without imposing a selection limit.
- Visualization revisions use the selected completed private image as the editing input, verify same-session/product ownership server-side, and save each revision separately; explicit customer changes override preservation defaults without changing generation limits.
- Use automatic visualization canvas sizing and natural-ratio previews with the shared image viewer; this avoids forcing product proportions and surrounding scenery into a square.
- Keep visitor chat history private behind the session-token function; administrator reads validate the JWT and protected admin role, and completed exchanges trigger fixed-recipient managed email notifications deduplicated by message ID.
- Compose the homepage gingerbread gallery as a sibling of the shop band in shared ShopSection so all language homepages have the same navigation target without duplicating page wiring.
- Use the shared ProductImageViewer for shop and product-page image enlargement, keeping image previews separate from product navigation and reusing accessible dialog controls.
- Keep legacy SEO URL aliases in `src/lib/seoPaths.ts` and route them to real pages; this prevents editorial links from landing on noindex pages.
- Keep `public/sitemap.xml` and `public/katalogs.html` synchronized with published product/blog URLs when the catalog changes; the HTML directory supplies crawlable links without a database query per crawler visit.
- Keep route metadata and HTML language in `useSeo`, using `useCurrentLang` for the selected language, and article JSON-LD in the article page; static HTML remains a fallback, not proof of server-rendered metadata.
- Editorial pages using the shared SEO landing layout explicitly opt into Article metadata; commercial pages do not, and organization references reuse the sitewide entity to avoid incomplete duplicates.
